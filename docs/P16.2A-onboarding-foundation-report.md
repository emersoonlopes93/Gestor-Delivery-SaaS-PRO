# P16.2A - Relatorio Fundacao do Onboarding

## 1. Status geral

Veredito: GO com ressalvas

O objetivo desta fase foi atendido:
- o backend nao conclui mais o onboarding sem validar requisitos reais;
- o frontend continua podendo usar estado local para navegacao visual, mas nao usa `localStorage` como fonte de verdade de conclusao;
- banner deixou de ser salvo como background global;
- bairro nao foi ativado como opcao real de onboarding;
- iFood continua opcional e sem promessas de importacao completa.

Ressalvas:
- o autocomplete unificado ainda nao entrou na UI do tenant;
- o dominio de modos de pedido ainda precisa de contrato explicito para pickup/dine-in;
- o storefront ainda nao renderiza um hero/banner publico dedicado, embora o contrato semantico ja esteja separado.

- fonte oficial mantida em `tenant_settings`

- origem canonica mantida em `tenant_settings.lat/lng`
- `delivery_coverage_configs` segue como fonte operacional

Horarios:
- fonte oficial: `tenant_operating_hours`

- fonte oficial: `tenant_settings.paymentMethods`
- `pixKey` continua em `tenant_settings`

Vitrine:

- banner/hero: separado semanticamente em `storefrontThemeJson.heroImageUrl` e `heroImageMediaId`

Conclusao do onboarding:
- fonte oficial: `tenant_onboardings.completedAt`
- readiness score continua diagnostico

## 3. Alteracoes na validacao de onboarding-complete

Implementado em `apps/api/src/tenant/onboarding.service.ts`.

Novo comportamento:
- `POST /tenant/onboarding-complete` primeiro roda validacao real dos dominios
- se faltar requisito, retorna erro `400` com payload estruturado
- se passar, grava `completedAt` e sincroniza flags derivadas

Novo contrato de checagem:
- `GET /tenant/onboarding-completion-check`
- resposta:
  - `canComplete`
  - `missingRequirements`
  - `warnings`
  - `nextRecommendedStep`
  - `completedAt`

Requisitos minimos ativos:
- nome da loja
- endereco estruturado
- coordenadas da loja
- pelo menos um horario aberto
- pelo menos um metodo de pagamento
- pelo menos um produto ativo
- configuracao minima de entrega, se delivery estiver habilitado

Campos visuais e opcionais nao bloqueiam:
- logo
- banner
- background
- iFood

## 4. Alinhamento dos steps frontend/backend

Implementado em `apps/web-tenant/src/features/onboarding/useOnboardingState.ts`.

O que mudou:
- o frontend agora sincroniza progresso com `PATCH /tenant/onboarding-step`
- o backend continua com as flags atuais
- o frontend passa a mapear steps do wizard para flags reais do backend

Mapeamento atual:
- `identity` -> `basicInfo`
- `location` -> `address`
- `hours` -> `operatingHours`
- `payments` -> `payments`
- `products` -> `catalog` + `menu`

Decisoes:
- `delivery` nao e marcado automaticamente so por entrar no step de localizacao
- `rules`, `storefront` e `review` continuam como progresso visual sem forcar flags de dominio inexistentes
- `completedAt` continua dependendo exclusivamente do backend

## 5. Correcao banner vs background

Implementado em:
- `packages/theme/src/index.ts`
